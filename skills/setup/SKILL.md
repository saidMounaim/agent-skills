# Setup

Puts all workflow state in files inside the repo, so any agent (Claude Code, Codex) and any new session can continue from them. Works with any tech stack.

## Preconditions

- The app already exists or is scaffolded. This workflow sits on top of a project; it does not create one.
- It is a git repository with a clean working tree. If not, stop and tell the user.
- `plan/build-plan.md` does not exist. If it does, stop and suggest `next`.

## Steps

1. Create this tree from this skill's `templates/` folder:

```
plan/
  project-plan.md     # user-owned: problem, users, data, stack, deploy
  build-plan.md       # user-owned: ordered feature checklist, stable IDs
  context/
    overview.md       # generated by discover
    current.md        # the ONE active spec (empty stub)
    findings.md       # findings ledger (empty stub)
    review.md         # latest audit receipt (empty stub)
  history/features/   # finished specs
  history/fixes/
  references/         # screens, mockups, reference images
  releases/           # release checklists
```

2. **Detect the stack and its commands.** Read `references/stacks.md` in this skill. Look at the repo's manifest and lock files, and at scripts the repo already defines (package scripts, Makefile, justfile, Taskfile). Prefer the repo's own scripts over defaults. Fill the Commands table: install, dev, typecheck, lint, test, e2e, build, deps-audit, migrate, and `verify` (every check chained, fastest first). Leave a row as `none` if the project has no such thing. Show the table and ask the user to confirm.
3. Append `templates/agents-block.md` to `AGENTS.md` (create it if missing) with the Commands table filled in.
4. `CLAUDE.md`: if missing, create it with one line: `Follow @AGENTS.md.` If it exists, add that line.
5. Existing project with working features: list them and propose them as checked items at the top of `build-plan.md`, so new work is numbered after them. Ask the user to confirm.
6. Tell the user what comes next:
   - fill the two plans themselves and run `discover` for the overview only, or
   - run `discover` for an interview that fills them.
   - No test runner → `tests`. No CI → `ci`. UI project with no `design.md` → `design`.
7. Offer a commit: `chore: add spec-driven workflow`. Commit only after the user says yes.

## Gotchas

- Never overwrite an existing AGENTS.md or CLAUDE.md. Append, and show the diff.
- Only list commands that really run in this repo. Try each once; a command that fails goes in as `none` with a note.
- Monorepo: one Commands table per app, or root commands that run everything. Ask which.
- Scaffolding the app is not a build-plan feature. It happens before item 1.
