# Project plan

> User-owned. Fill it yourself or run `discover`. Leave a line blank rather than guess.
> When this and build-plan.md are ready, `discover` writes `context/overview.md`.

## 1. Problem
What problem does this solve? One or two sentences.

## 2. Users
Who uses it? Main user types and what each needs.

## 3. Features (MVP)
One line per feature. The ordered, numbered version goes in build-plan.md.

## 4. Data
What is stored? Main entities and how they relate. Anything that must never change once written?

## 5. Tech
Frameworks, database, ORM, UI library, auth, PDF/email/payment services, AI services.

## 6. Money
How does it make money (if at all)? Which currencies and taxes does the product itself handle?

## 7. UI / UX
Look and feel. Reference sites or screenshots (store images in `plan/references/`).

## 8. Deployment
Host, build and start commands, env variable NAMES (never values), database/storage, cron or workers, health check path, domain.

## 9. Constraints (optional)
Expected scale, internal or public, multi-tenant or single, trust level of users, compliance (invoices, VAT/TVA, GDPR), languages, explicit non-goals.
